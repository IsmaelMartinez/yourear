# ADR 008: SNR in the Speech-in-Noise Test

## Status
Accepted (revised: word clips through Web Audio replace `speechSynthesis`)

## Context
The speech-in-noise test reports an SNR-50: the signal-to-noise ratio at which the user identifies half the words. Noise is pink noise played through Web Audio (`src/audio/speech-noise.ts`). Words were first spoken with the Web Speech API (`speechSynthesis`), which plays through the browser's own speech output. That output cannot be routed into an `AudioContext`, so its level could not be measured or scaled against the noise, and the SNR was only nominal: it depended on the voice, the platform and the OS speech volume.

## Decision
Play pre-generated clips of the test words through the same `AudioContext` as the noise, so both levels are known.

The 30 clips in `public/speech/<word>.mp3` are generated by `scripts/generate-speech-clips.sh` with the open-source espeak-ng synthesiser (GPL-3.0; its output audio is not covered by the licence), voice `en-us` at 140 words per minute. The script reads the words from `WORD_LISTS`, trims leading and trailing silence below -50 dB, normalises each clip to -20 dBFS RMS, and encodes it as 22.05 kHz mono MP3 at 48 kbps (about 97 KB for all 30). A test checks that exactly one clip ships per word. Rerun the script when a word list changes.

At runtime `speakWord` fetches a clip once from `import.meta.env.BASE_URL`, decodes it with `decodeAudioData` and caches the decoded buffer with its measured RMS. Each word plays through a `GainNode` that brings its measured RMS to `SPEECH_LEVEL_DBFS` (-25 dBFS, leaving headroom for the -10 dB SNR step, where the noise's ~13 dB crest factor would otherwise clip). The pink-noise buffer's RMS is measured when it is generated, and its gain is set so the noise RMS is `noiseLevelDbfsForSNR(snr) = SPEECH_LEVEL_DBFS - snr`. The SNR is therefore the difference of the two RMS levels, measured on the samples actually played, rather than a nominal value.

One looping noise source is started per run from a cached pink-noise buffer, and level changes ramp its gain with `setTargetAtTime` rather than rebuilding the source. `stopSpeech()` stops the playing word and cancels one still loading; the screen's cleanup calls it with `stopNoise()`. The clips are in the Workbox precache, so the test works offline.

## Consequences
### Positive
- The SNR is exact in the digital domain and the same on every device and browser
- Speech no longer depends on which voices the platform has installed
- Steps between SNR levels are consistent, because only the noise moves
- No clicks or doubled noise from restarting sources between words

### Negative
- About 97 KB of audio is shipped and precached
- Absolute presentation level is still uncalibrated in dB SPL, like the rest of the app, so scores are only roughly comparable with clinical SNR-50 values, which also use natural speech rather than synthesised words
- Changing a word list means regenerating clips with espeak-ng and ffmpeg installed
